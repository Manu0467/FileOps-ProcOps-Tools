# Database Format

## 1. DB Format

The file generated by the manager (default `inventory.db`) is a binary file composed of 3 sections:

1. **The header section**
   * Represented by the `header_db` structure, which contains:
     * a 5-byte magic (including the null terminator at the end), which for this database is `INV4`.
     * the database version, represented by an `int32`.
     * the completion indicator, also represented by an `int32`.
     * the total number of indexed files, which is also an `int32`.
     * the total number of workers that contributed to this database (`int32`); an `int32` was chosen to ensure it maintains the same size across all operating systems.

2. **The file records section (file_records)**
   * Starts immediately after the header and contains a number of `file_record_count` structures of type `FileRecord`. These records were initially stored in a temporary file that is deleted upon program completion.
   * Each record stores: the PID, GID, file size, path, last modification (`mtime`), file type (`mode`), and the 65-byte SHA256 hash.

3. **The worker statistics section (worker_stats)**
   * Starts immediately after the `file_records` area.
   * To be accessed in `--dump` mode, the manager calculates the offset where this area begins and moves the cursor using `lseek`.
   * This area contains a number of `worker_count` structures of type `WorkerStats` where the number of processed files, the PID, or the `worker_id` are recorded.

## 2. DB Validity Conditions

The database is considered valid if it simultaneously meets the following conditions in `--verify` mode:
* The `header_db` structure must be fully readable (comparing the size of the read space with the size of the `header_db` structure).
* It must have a valid magic number (`INV4`).
* The `complete` flag must have the value 1, indicating that the program finished successfully.
